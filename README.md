# Buildbook

Локальное браузерное приложение для учёта сборок ПК, складских комплектующих, касс, доходов, расходов, долгов, инвестиций и командных задач.

## Автономный HTML и ZIP проекта

`Buildbook-standalone.html` — автономная копия приложения: локальная библиотека XLSX и слой IndexedDB встроены внутрь одного HTML-файла. Его можно открыть двойным кликом; данные останутся в IndexedDB браузера. После изменения `index.html`, `repository.js` или версии SheetJS пересоберите файл командой `node scripts/build-standalone.mjs`. Workflow `.github/workflows/build-standalone.yml` также пересобирает и фиксирует автономный файл после push в `main` и рабочие ветки. Установка PWA и Service Worker доступны только при запуске через HTTP(S). Полный ZIP исходного проекта можно скачать через **Code → Download ZIP** на GitHub.

## Запуск

Откройте `index.html` в современном браузере. Основные данные сохраняются локально в IndexedDB этого браузера. Интернет и внешние CDN для работы интерфейса не требуются.

Для установки в виде PWA и гарантированной работы Service Worker откройте проект с локального или статического HTTP(S)-хоста. При открытии через `file://` установка PWA и офлайн-кеш Service Worker недоступны.

Фотографии при добавлении проверяются, пропорционально уменьшаются до максимальной стороны 1100 пикселей и сохраняются как JPEG; ошибка отдельного файла не блокирует обработку остальных фото. В интерфейсе изображения представлены как data URL, а в IndexedDB сохраняются бинарными `ArrayBuffer`-пакетами с MIME-типом. Прямую запись `Blob` в IndexedDB заменили на бинарный формат, чтобы обойти зависание WebKit. Старые записи с `Blob`, `ArrayBuffer` и data URL поддерживаются при чтении.

## Текущий статус

Текущая версия интерфейса — **2.21**. Календарные даты формируются по локальному календарю устройства; системная тема обновляется при изменении темы ОС, а установка PWA сопровождается инструкциями для браузеров и iOS.

В версии 2.21 реализованы разделы «Долги» и «Инвестиции». Долги учитывают направление, контрагента, срок возврата, частичные платежи, архив и историю. Инвестиции учитывают первоначальное вложение, пополнения, выводы, ручную текущую оценку и результат с учётом выведенных средств. Новые движения меняют баланс выбранной кассы, но не попадают в обычные отчёты о доходах и расходах, чтобы возврат основного долга и перемещение капитала не считались заработком или расходом. Оба раздела входят в миграцию схемы 4, JSON/ZIP-бэкапы, CSV- и XLSX-импорт/экспорт. В набор добавлены проверки миграции и финансовых движений.

Это рабочий локальный MVP, а не многопользовательская облачная система: данные хранятся в IndexedDB конкретного браузера и устройства. Перед использованием для реального финансового учёта нужна регулярная резервная копия и успешный браузерный прогон на поддерживаемых движках.

## Версионирование данных и сохранение

Buildbook хранит данные приложения в записи IndexedDB `s`, а фотографии — отдельно в записи `p` в виде бинарных `ArrayBuffer`-пакетов с MIME-типом; приложение восстанавливает из них data URL для отображения. Внутри профиля используется поле `schemaVersion`; текущая версия схемы данных — **4**. Основные сущности (кассы, партии, сборки, операции, долги, инвестиции, складские события, задачи и пункты чек-листа) содержат `id`, `createdAt`, `updatedAt`, `deletedAt` и собственное поле `schemaVersion`.

Миграции выполняются последовательно и только при необходимости:
- схема 0 (старый профиль без номера версии) → схема 1: нормализация обязательных списков, категорий, касс и системных настроек без удаления существующих партий, сборок, операций, задач и заметок;
- схема 1 → схема 2: добавление отдельного списка пунктов чек-листа задач `checklist`, если его ещё нет;
- схема 2 → схема 3: добавление временных меток и номера схемы для основных сущностей; удалённым записям в корзине присваивается `deletedAt`, активным — `deletedAt: null`;
- схема 3 → схема 4: добавление коллекций долгов и инвестиций, а также настройки включения нового раздела. Старые операции, кассы, партии, сборки, задачи, фотографии и заметки не удаляются.

Профиль, созданный более новой версией схемы, не открывается старой версией приложения: показывается ошибка, а данные не заменяются пустым состоянием. Некорректный корневой формат также отклоняется. Состояние, журнал и фотографии сохраняются одной транзакцией IndexedDB. Доступ к базе изолирован в `repository.js`: модуль управляет соединением, читает три записи единым снимком и предоставляет атомарную запись профиля. Он не содержит бизнес-логики и не меняет `schemaVersion`. Отдельная техническая ревизия в записи `r` увеличивается при каждой успешной записи; сравнение и сохранение выполняются в одной read/write-транзакции. При конфликте приложение останавливает сохранение в старой вкладке, показывает предупреждение и предлагает скачать ZIP-копию её текущего состояния. Вкладки одного профиля дополнительно обмениваются уведомлениями через BroadcastChannel; если API недоступен, защиту обеспечивает проверка ревизии в IndexedDB. При ошибке записи приложение сообщает о проблеме; отложенное сохранение дополнительно сбрасывается при уходе со страницы или переводе вкладки в фон.

При развитии структуры данных номер схемы нужно увеличивать и добавлять отдельный последовательный шаг миграции. Для старых записей без метаданных время создания и изменения заполняется моментом миграции; исходные бизнес-даты закупки, сборки и операции не меняются. Миграция схемы данных не меняет версию самой объектной базы IndexedDB: она хранится в поле профиля и применяется к данным приложения.

## Журнал и безопасная отмена действий

Журнал хранит адресные изменения, а не только полный снимок профиля. При отмене выбранной записи приложение восстанавливает только затронутые поля, поэтому последующие независимые действия остаются на месте. Если какое-либо затронутое поле после выбранного действия изменилось ещё раз, отмена блокируется до устранения конфликта и не меняет данные.

Каждая отмена сама записывается в журнал как отдельное действие. Старые записи прежнего формата автоматически преобразуются из сохранённых снимков в наборы изменений. Перед преобразованием старые снимки проходят нормализацию схемы, чтобы отмена не затрагивала поля, добавленные миграциями профиля.

## Чек-лист задач

В разделе «Задачи» есть отдельный чек-лист для коротких пунктов без срока и привязки к сборке. Пункт можно добавить, отметить выполненным или удалить. Чек-лист хранится в профиле, входит в JSON/ZIP-резервную копию и восстанавливается при объединении или полной замене профиля. При импорте повторной копии записи сопоставляются по ID, поэтому повторное восстановление не должно создавать дубликаты.

## Глобальный поиск и горячие клавиши

Поиск вызывается сочетанием `Ctrl+K` (на устройствах Apple — `⌘K`) и ищет по комплектующим, сборкам, операциям и задачам. Выбор результата открывает соответствующую запись для редактирования. Для перехода по разделам используйте `Ctrl+Alt+1…9`: обзор, дашборд, склад, сборки, деньги, отчёты, задачи, журнал и настройки. Быстрые действия: `Ctrl+Alt+N` — новая сборка, `Ctrl+Alt+P` — закупка, `Ctrl+Alt+T` — задача, `Ctrl+Alt+I` — доход, `Ctrl+Alt+E` — расход. `Esc` закрывает открытое модальное окно.

## Дашборд и оборачиваемость

Дашборд показывает стоимость доступного склада, число проданных ПК и заработок за текущий месяц, количество проблемных деталей, количество сборок по каждому статусу и балансы касс. Дополнительные блоки рассчитывают среднее время от поступления детали до установки (с весом по количеству деталей), средний срок от сборки до продажи, выводят незакрытые сборки старше 30 дней и последние действия из журнала. Стандартный график маржи сортирует проданные ПК по убыванию процента маржи. Старый стандартный набор графиков автоматически обновляется; вручную настроенные наборы не заменяются.

## Финансовые отчёты

Раздел «Отчёты» содержит четыре вкладки:

- «Расходы» и «Доходы» — помесячная матрица по группам и категориям, итог по каждой группе, итог по году и среднемесячное значение для каждой строки;
- «Сводка» — доходы, расходы и чистые сбережения по каждому месяцу, годовые итоги, среднее за месяц и график;
- «Прибыль по сборкам» — проданные ПК по дате продажи с выручкой, зафиксированной себестоимостью, прибылью и маржой.

Год выбирается из лет, присутствующих в операциях и датах продажи сборок. Переводы между кассами исключены из матриц и сводки. Любой из четырёх отчётов можно скачать в CSV.

## Переводы между кассами

В разделе «Деньги» можно создать перевод между двумя разными кассами, указав дату, сумму, назначение и комментарий. Перевод хранится одной отдельной операцией: баланс исходной кассы уменьшается, баланс целевой увеличивается. Перевод можно отредактировать или удалить; при этом доходы, расходы, прибыль и соответствующие графики не меняются. В CSV-выгрузке перевод помечается отдельным типом и содержит обе кассы. Движения долгов и инвестиций также имеют отдельные типы операций и не входят в обычные суммы доходов/расходов.

## Долги и инвестиции\n\nРаздел можно включать и отключать в настройках; отключение скрывает интерфейс, но не удаляет данные и не отменяет связанные движения по кассам. В «Долгах» фиксируются выданные суммы («Мне должны») и полученные займы («Я должен»), срок возврата, контрагент и касса. Частичный или полный возврат добавляется отдельным платежом; остаток долга пересчитывается, а история остаётся доступной. Архивирование не удаляет долг и блокирует новые платежи до восстановления из архива.\n\nВ «Инвестициях» фиксируются тип актива, площадка, первоначальное вложение, пополнения, выводы и текущая оценка, которую пользователь обновляет вручную. Результат рассчитывается как текущая оценка плюс все выведенные средства минус все вложения. Вывод ограничен текущей оценкой; закрыть инвестицию можно после обнуления оценки. Для каждого движения указывается касса. Возврат долга и движение инвестиционного капитала меняют остаток кассы, но не входят в P&L отчёты доходов/расходов. Записи и связи с операциями входят в JSON/ZIP-копии и таблицы CSV/XLSX.\n\n## Восстановление JSON-бэкапа

При загрузке JSON-копии можно выбрать режим «Добавить к существующим данным» или «Заменить все текущие данные». Добавление сохраняет существующие записи, пропускает совпадающие ID, сопоставляет кассы, партии и сборки, переносит задачи, складские события, справочники и фотографии. Повторное добавление той же копии не создаёт дубликаты по ID. При замене приложение перед восстановлением автоматически скачивает отдельный файл `buildbook-before-restore-ДАТА.json` с текущими данными и фотографиями. После завершения показывается сводка результата.

## Импорт и экспорт XLSX

В версии 2.3 добавлена локальная библиотека SheetJS CE 0.20.3 (`vendor/xlsx.full.min.js`). Файл библиотеки поставляется вместе с приложением и включён в офлайн-кэш PWA: для импорта и экспорта Excel интернет не нужен.

В «Настройках» доступны:
- экспорт всех разделов одной книгой XLSX: «Кассы», «Склад», «Сборки», «Долги», «Инвестиции», «Транзакции», «Задачи», «Расходы», «Доходы», «Сводка» и «Прибыль сборок»;
- отдельная выгрузка четырёх финансовых отчётов;
- импорт книги XLSX/XLS с предпросмотром листов, выбором назначения и сопоставлением колонок для каждого листа. Импортируются кассы, складские партии, сборки, долги, инвестиции, финансовые операции и задачи; связи долгов и инвестиций с операциями сохраняются по ID.

При импорте листы обрабатываются в порядке зависимостей: сначала складские партии, затем сборки, затем операции. Это позволяет восстанавливать связи по ID партии и ID сборки. Ошибочные строки пропускаются с объяснением, а в конце показываются итоги по каждому листу. Для сохранения авторства и условий распространения SheetJS в `vendor/LICENSE-SheetJS.txt` включён полный текст Apache License 2.0 и указаны источник с версией библиотеки.

## ZIP-карточка сборки

В списке сборок доступны действия «TXT», «Печать» и «ZIP». TXT содержит реквизиты и состав сборки, «Печать» открывает системное окно браузера, а ZIP выгружает отдельную карточку: документ Word в формате DOCX (пакет OOXML), структурированные данные сборки (`card.json`) и папку `photos/`. Импорт карточки находится рядом с кнопками списка сборок. При восстановлении проверяются ID и реквизиты исходных партий, свободное количество и уникальность номера сборки. Сначала должны быть импортированы соответствующие партии склада с исходными ID. Отдельная карточка не переносит кассовые операции; для полного переноса профиля используйте ZIP-бэкап.

## Резервная копия ZIP

Отметка «Последняя копия» обновляется после формирования файла и вызова скачивания. Если создание архива или запуск скачивания завершается ошибкой, предыдущая дата сохраняется.

В разделе «Настройки» доступны JSON-копия и полный ZIP-бэкап. ZIP содержит `backup.json` и отдельные файлы фотографий активных и удалённых сборок. При восстановлении ZIP автоматически собирается в структуру обычной резервной копии и открывается стандартное окно с режимами «Добавить» и «Заменить всё». Перед заменой сохраняется защитная JSON-копия текущих данных. ZIP-бэкап Buildbook использует несжатые ZIP-записи, чтобы архив мог формироваться и читаться локально без внешней библиотеки или сетевых запросов; повреждение файлов проверяется по CRC.

## Корзина

Удаление партий, сборок, финансовых операций и задач перемещает запись в отдельный раздел «Корзина». При удалении партии или сборки можно также переместить связанную финансовую операцию. Фотографии сборки сохраняются в корзине. Запись можно восстановить или удалить окончательно. Восстановление партии и сборки проверяет наличие конфликтующих ID, исходных партий и свободного количества. Для удалённой продажи комплектующего сохраняется контрольное состояние склада и сборки: если оно изменилось, восстановление блокируется, чтобы не перезаписать новые движения.

## Импорт CSV

В «Настройках» выберите «Импорт CSV». Мастер показывает первые строки файла, определяет разделитель (`;`, `,` или табуляцию), учитывает BOM, кавычки и разделители внутри ячеек. Можно выбрать тип данных — склад, сборки, операции, кассы, задачи, долги или инвестиции — и вручную сопоставить столбцы с полями Buildbook. Для операций доступен тип по умолчанию, если в файле нет столбца с типом.

Импорт проверяет даты, числа, количества, уникальность ID и ссылки на партии/сборки. Корректные строки добавляются, ошибочные пропускаются; в итоговом окне показываются количества добавленных и пропущенных строк и причины ошибок. Идентификаторы из CSV сохраняются. Состав сборки можно импортировать в поле «Комплектующие» в формате `ID-партии:количество`, несколько позиций разделяются символом `|`, а для проблемной детали используется суффикс `:problem`. Экспорт CSV содержит ID и связи, необходимые для обратного импорта.

Поддерживается импорт и экспорт CSV для склада, сборок, финансовых операций, касс, задач, долгов и инвестиций. Тип кассовой или задачной таблицы определяется автоматически; для остальных типов мастер предлагает выбор вручную. Связанные продажи комплектующих при импорте CSV/XLSX сохраняются как исторические финансовые снимки: остатки партии и состав сборки импортируются отдельно, поэтому удаление такой импортированной операции не изменяет склад повторно. Для переноса полного текущего состояния предпочтительно использовать JSON- или ZIP-бэкап. Импорт и экспорт книг Excel описаны в разделе «Импорт и экспорт XLSX».

## Проблемные остатки и списания

У каждой партии отдельно учитываются нормальные, проблемные и списанные единицы. Можно отметить проблемой часть свободного нормального остатка, указав причину, и частично снять отметку после повторной проверки. Проблемные единицы не выбираются в сборку по умолчанию: для их установки нужно выбрать отдельную помеченную позицию. Свободные проблемные детали можно списать с датой и обязательной причиной. События маркировки, снятия отметки и списания остаются в отдельной истории. Списание не меняет кассовый баланс и не удаляет исходную партию.

Старые записи со свойством `problem` автоматически преобразуются в количественную модель при загрузке, а уже установленные в сборки проблемные детали сохраняют свою пометку. Удаление доходной операции по продаже проблемной детали возвращает её в склад и, при необходимости, в исходную сборку с тем же статусом.

## Продажа комплектующих и настройка категорий

В версии 2.2 добавлены безопасное восстановление JSON-бэкапа, импорт CSV и количественный учёт проблемных остатков, а также множественная продажа комплектующих. В версии 2.3 добавлены импорт/экспорт XLSX. В версии 2.4 — корзина с проверкой восстановления. В версии 2.5 — импорт касс и задач из XLSX и полный ZIP-бэкап профиля. В версии 2.6 — экспорт и импорт ZIP-карточки отдельной сборки с документом, составом и фото. В версии 2.7 — хранение фото в IndexedDB как Blob с автоматическим чтением старого формата; текущая версия использует бинарные ArrayBuffer-пакеты для совместимости с WebKit. В версии 2.8 — укрепление локального хранилища и контроль версии профиля. В версии 2.9 — чек-лист задач и миграция профиля на схему 2. В версии 2.10 — TXT-экспорт и системная печать карточек сборок. В версии 2.12 — метаданные записей и миграция профиля на схему 3. В версии 2.13 — оценка локального хранилища и запрос постоянного хранения из настроек. В версии 2.16 — демо-данные с безопасным удалением, настраиваемый лимит журнала и недостающие заглушки настроек. В версии 2.17 — устойчивое сжатие фото с обработкой ошибок, фиксация даты бэкапа после формирования и запуска скачивания, обновление кеша PWA. В версии 2.18 — календарные даты формируются по локальному часовому поясу, а системная тема автоматически обновляется при изменении темы ОС.

- из одного окна можно выбрать несколько партий и для каждой отдельно задать количество и цену продажи за штуку;
- в продажу включаются как свободные остатки склада, так и детали, установленные в незавершённые сборки;
- детали из сборок выделяются отдельно; после продажи соответствующее количество удаляется из состава конкретной сборки и вычитается из партии склада;
- по каждой продаже создаётся доходная операция с сохранённой себестоимостью, выручкой и валовой прибылью;
- при удалении такой операции количество возвращается на склад, а в незавершённую сборку — если сборка ещё не продана;
- исчерпанные партии скрываются из обычного списка склада, но остаются в истории и доступны через фильтр.

В «Настройках» можно создавать, переименовывать, скрывать и удалять группы и категории доходов/расходов. Категории, используемые в истории, предлагается скрыть вместо удаления; типы склада защищены от удаления, но допускают переименование.

**Важно по финансовому учёту:** сумма продажи полностью увеличивает баланс кассы. Себестоимость сохраняется в самой операции, а валовая прибыль рассчитывается отдельно как выручка минус себестоимость. Закупочный расход не дублируется повторно при продаже детали.

## Автоматические тесты

В каталоге `tests/` находится браузерный набор тестов текущего функционала.

- `tests/test-runner.html` — тестовая страница с отчётом по каждому сценарию;
- `tests/run-browser.mjs` — запуск набора через Playwright в Chromium, Firefox или WebKit (Safari engine);
- `.github/workflows/browser-tests.yml` — матрица `index.html` и автономной сборки в Chromium, Firefox и WebKit при push, pull request и ручном запуске. Chromium и Firefox проверяют профиль с данными и фото суммарным объёмом более 10 МБ; WebKit отдельно проверяет компактный профиль и полный цикл сохранения/восстановления бинарных ArrayBuffer-фотографий. Это покрывает проблемный путь WebKit без большого тестового профиля.

Для локального запуска тестов достаточно Node.js и Python 3 (только тестовая среда; самому приложению Node.js не нужен). Перед проверкой автономной версии можно пересобрать её так:

```bash
node scripts/build-standalone.mjs
```

Затем установите Playwright и запустите тесты:

```bash
npm install --no-save --no-package-lock playwright
npx playwright install chromium
python3 -m http.server 4173
```

Затем откройте `http://localhost:4173/tests/test-runner.html`. Тесты используют отдельную базу IndexedDB `buildbook-test` и не изменяют обычные данные приложения.

Набор содержит **126 браузерных сценариев** и запускается в шести комбинациях: `index.html` и автономный `Buildbook-standalone.html` в Chromium, Firefox и WebKit. Перед тестами автономная версия пересобирается, а CI проверяет, что коммитный файл совпадает с исходниками. В нём есть отдельные проверки импорта CSV касс, задач, долгов и инвестиций, кругового XLSX-переноса новых разделов и самодостаточности автономной сборки. Проверяются миграция схемы 3 → 4, выдача и возврат долгов, запрет переплаты, движения инвестиционного капитала, а также восстановление связей из бэкапа. Сценарии включают миграции схем 0 → 1 → 2 → 3 → 4, идемпотентность миграций, защиту от повреждённых и более новых схем, операции чек-листа, импорт/экспорт и печать карточек сборок, проверку структуры DOCX, адресный откат независимых действий, блокировку конфликтного отката, отмену складского и финансового действий, а также миграцию старого журнала.

## Демо-данные и настройки журнала

В настройках можно добавить демонстрационные партии, сборки, операции и задачи, не заменяя реальные записи. Удаление очищает только записи, помеченные как демо. Лимит журнала настраивается от 20 до 1000 записей; журнал экспортируется в CSV. Модуль «Долги и инвестиции» реализован и управляется настройкой. Защита полей реализована для локальной базы: выбранные финансовые и личные значения шифруются AES-GCM-256, ключ выводится через PBKDF2-SHA-256; при каждом новом запуске требуется разблокировка. Экспортированные JSON/ZIP/CSV/XLSX-копии остаются незашифрованными; фотографии и уже разблокированная сессия не входят в область защиты. Пароль нельзя восстановить.

## Хранение данных

Данные не отправляются на сервер: они находятся в IndexedDB конкретного браузера и устройства. Регулярно скачивайте резервную копию из раздела «Настройки». Очистка данных браузера может удалить локальную базу.
