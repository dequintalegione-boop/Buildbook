## Статус по этапам

| Этап | Статус | Примечание |
|---|---|---|
| 1. Аудит | Выполнен | Зафиксированы архитектура, уже вошедшие PR и gaps; см. аудит |

Установка и мастер | Частично | Добавлен standalone установщик с однократным выбором и сохранением папки; мастер сохраняет безопасный шаг и профиль проверенного бота без токена, при продолжении требует повторно ввести и проверить токен. Автоматическая установка Node.js и полный 12-шаговый сценарий ещё не реализованы |
| 5. Белый список | Реализация в PR #25 | Active/disabled, addedAt, синхронизация активных ID с gate, обратная совместимость v1 |
| 6. Команды и финансы | Реализация в PR #25 | Добавлены persistent switches; income/expense/stats выключены по умолчанию и проверяются на host перед финансовой логикой |
| 7. Журнал и диагностика | Реализация в PR #25 | Неограниченное хранение по умолчанию, offset pagination, поиск, фильтры статуса/типа, экспорт полной истории, события входящих/отклонённых сообщений и результатов команд; добавлена latency и stale-индикация |
| 8. Автозапуск и восстановление | Частично | Scheduled Task и диагностика есть; аварийное восстановление требуется подтвердить на Windows |
| 9. Тестирование | В работе | Добавлены регрессионные тесты; нужны CI и проверка установленного PWA на Windows |

## Что сделано в текущем инкременте

- [x] Снято автоматическое ограничение журнала в 500 событий по умолчанию.
- [x] Добавлена пагинация API журнала.
- [x] Добавлены поиск, фильтр по статусу, загрузка следующей страницы и экспорт всей истории JSON.
- [x] Добавлены поля active и addedAt для доверенных пользователей.
- [x] Отключённые пользователи сохраняются, но не проходят серверный gate.
- [x] Запрещено отключать всех пользователей.
- [x] Сохранена обратная совместимость старых метаданных белого списка.
- [x] Добавлены тесты для истории >500 событий, пагинации и allowlist API/handlers.
- [x] Добавлены настройки исполнения команд (income/expense/stats выключены по умолчанию, help включён).
- [x] Добавлена проверка переключателей на серверной стороне до записи/чтения финансовых данных.
- [x] Добавлено измерение Bot API latency с кэшированием и stale-индикатором.
- [x] В журнал пишутся безопасные события приёма/отклонения сообщений, результатов команд, финансовых операций и ошибок обработки; исходный текст сообщений и токены не сохраняются.
- [x] Добавлены фильтры по типу события и поиск по Telegram ID/operation ID на стороне локального хоста по всей истории, а не только по загруженной странице.
- [x] Карточки событий показывают Telegram ID, Update ID и Operation ID, если они присутствуют.
- [x] Мастер сохраняет безопасный прогресс после проверки бота; токен не сохраняется в localStorage и повторно запрашивается при продолжении после закрытия приложения.

## Следующие обязательные задачи

1. Довести установщик до полноценного пакета с автоматизированной установкой Node.js/зависимостей с явным согласием пользователя и безопасным продолжением после перезапуска.
2. Расширить мастер до полного сценария из 12 шагов исходного плана: выбор/проверка папки, подготовка структуры, проверка локального сервера, запуск и итоговая диагностика.
3. Проверить Windows Task Scheduler: аварийно завершить host, дождаться повтора, подтвердить восстановление polling без второго экземпляра.
4. Пройти полный чек-лист раздела 9 исходного плана на установленном PWA.
