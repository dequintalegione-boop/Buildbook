# История версий Buildbook

Краткий журнал изменений интерфейса и связанных возможностей.  
Текущая зафиксированная версия UI в приложении: **2.35** (в футере настроек).  
Изменения Telegram/host после 2.35 собраны как **2.36** (ожидают поднятия номера в UI).

---

## Версия 1.x — основа

- Учёт сборок ПК, складских партий и касс.
- Доходы, расходы, базовые отчёты.
- Локальное хранение данных в браузере (IndexedDB).
- Темы оформления и адаптивная навигация.

## Версия 2.36 — Telegram из приложения и устойчивость host

*(изменения внесены в код; номер в футере UI при желании поднять с 2.35 на 2.36)*

### Интерфейс
- Полноценная вкладка **Telegram** с дашбордом состояния.
- **Мастер подключения** (токен → allowlist → команды → включение polling).
- Проверка токена через Bot API с показом имени/@username бота.
- Управление **allowlist** и **командами** бота без правки файлов вручную.
- Кнопки включения/выключения polling, старт/стоп сервиса.
- Индикация **«Бот online · принимает сообщения»**.
- Лента **последних событий** обработки (без текста сообщений).
- Offline-баннер и подсказки при недоступном host / stalled polling.
- Кнопка снятия **stale-блокировок** после аварийного завершения.

### Локальный host
- Проверка и сохранение токена (`validate-token`, `save-token`) с записью в `.env` и backup.
- Runtime-конфиг allowlist и флагов команд.
- Hot enable/disable polling с записью `BUILDBOOK_TELEGRAM_ENABLED`.
- Compose Telegram-сервиса по требованию (не только при старте с ENABLED=true).
- Безопасный reclaim instance-lock только если PID владельца мёртв.
- Auto-restart цикла Telegram после сбоя (backoff).
- Расширенный `/api/telegram/status`: `recentEvents`, `acceptingMessages`.

### PWA / кэш
- Кэш Service Worker: `buildbook-49` → **`buildbook-50`**.
- Для оболочки приложения — **network-first** (чтобы Edge/Яндекс не держали старый UI).
- Перезагрузка страницы при смене активного service worker.
