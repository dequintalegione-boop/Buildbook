# Настройка локального хоста Buildbook (Windows)

## Требования

- Windows 10/11;
- Node.js 22 LTS (команда `node` должна быть доступна в PowerShell);
- браузерный запуск Buildbook через HTTP на `localhost` или `127.0.0.1` для защищённой сессии локального API. Открытие через `file://` не подходит для bootstrap из-за браузерного Origin `null`.

## Первичный запуск

1. В корне проекта скопируйте `.env.example` в `.env` (скрипт первого запуска сделает копию автоматически).
2. Укажите абсолютные пути к профилю и файлам очереди.
3. Сгенерируйте отдельный случайный ключ API:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

4. Вставьте результат в `BUILDBOOK_LOCAL_API_TOKEN`. Не используйте пароль от других сервисов.
5. Заполните токен Telegram-бота и числовой ID пользователя, которому разрешён доступ. Эти значения хранятся только в `.env`.
6. Оставьте `BUILDBOOK_TELEGRAM_ENABLED=false`.
7. Запустите `scripts/start-buildbook-local-host.ps1`.
8. Откройте `http://127.0.0.1:43127/` (или адрес/порт, заданные в `.env`). Локальный хост сам раздаёт интерфейс и API с одного origin; отдельный статический сервер не нужен.
9. Перейдите во вкладку Telegram и подключитесь ключом `BUILDBOOK_LOCAL_API_TOKEN`. Ключ используется только для первоначального обмена на HttpOnly-сессию и не сохраняется браузером.

Локальный web host отдаёт только фиксированный список публичных ресурсов интерфейса: `index.html`, необходимые скрипты, библиотеку XLSX, manifest, иконку и Service Worker. `.env`, `.git`, `data/`, профиль, очередь Telegram, логи и произвольные файлы не входят в allowlist и не раздаются. Поддерживаются только GET/HEAD; каталог-листинг отключён. Интерфейс и API используют один hostname и порт.

## Автозапуск Windows

После успешного ручного запуска можно установить задачу Планировщика заданий для текущего пользователя:

```powershell
.\scripts\install-buildbook-autostart.ps1
```

Задача запускается при входе пользователя, работает без повышенных прав, не создаёт параллельные экземпляры и повторяет запуск после аварийного завершения (до пяти попыток с минутным интервалом). Для удаления:

```powershell
.\scripts\uninstall-buildbook-autostart.ps1
```

Для временной остановки используйте `Stop-ScheduledTask -TaskName 'Buildbook Local Host'`; для запуска — `Start-ScheduledTask -TaskName 'Buildbook Local Host'`.

## Важное ограничение Telegram

Telegram polling **по умолчанию выключен**. Сначала откройте Buildbook через локальный host, перейдите во вкладку Telegram и подключитесь ключом `BUILDBOOK_LOCAL_API_TOKEN`. Затем в настройках импорта создайте резервную копию IndexedDB, перенесите профиль в пустой файловый профиль, проверьте read-back и SHA-256 и подтвердите переключение на канонический профиль. После перезапуска проверьте, что вкладка Telegram показывает активное каноническое хранилище. Только после этого разрешается установить `BUILDBOOK_TELEGRAM_ENABLED=true` в `.env` и перезапустить host. Если интерфейс остаётся на IndexedDB, Telegram включать нельзя: это два независимых финансовых журнала.

Автозапуск хоста поднимает локальный web/API host на одном loopback-порту. Включение Telegram после завершения миграции будет происходить через `.env` и перезапуск задачи. Отдельная Windows-служба с установщиком и интерактивным управлением пока не реализована. Режим хранения обычного UI выбирается явно после проверенного импорта; при потере сессии приложение блокирует запуск, а не переключается на IndexedDB.

Ключ первоначального подключения обменивается на HttpOnly-сессию с `SameSite=Strict`; браузерный JavaScript не получает значение cookie. Токен Telegram-бота никогда не передаётся браузеру. Локальный хост пишет журнал в `data/local-host.log`; при достижении 5 МБ предыдущий файл ротируется в `.1`.

## Безопасность

- Не коммитьте `.env`; он исключён через `.gitignore`.
- Не отправляйте `.env` в чат и не вставляйте токен Telegram-бота во вкладку браузера.
- Используйте только loopback-адреса для локального API.
- Не открывайте порт локального API в сеть и не меняйте bind host на `0.0.0.0`.
- Регулярно создавайте резервные копии профиля.
