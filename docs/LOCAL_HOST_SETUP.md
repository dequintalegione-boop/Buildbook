# Настройка локального хоста Buildbook (Windows)

## Требования

- Windows 10/11;
- Node.js 22 LTS или новее (команда `node` должна быть доступна в PowerShell; скрипт запуска проверяет установленную версию до работы с `.env`);
- браузерный запуск Buildbook через HTTP на `localhost` или `127.0.0.1` для защищённой сессии локального API. Открытие через `file://` не подходит для bootstrap из-за браузерного Origin `null`.

## Первичный запуск

1. Скачайте `scripts/install-buildbook.ps1` из репозитория и запустите его обычным пользователем Windows. Скрипт скачает архив проекта с GitHub, при первой установке откроет выбор папки приложения и сохранит выбранный путь в `%LOCALAPPDATA%\\Buildbook\\install-path.json`. При повторном запуске папка не запрашивается заново; обновление сохраняет `.env` и пользовательские данные.
2. Установщик проверит Node.js 22 LTS или новее. Если Node.js отсутствует или устарел, он запросит разрешение на установку/обновление через Windows Package Manager (winget) с обычным подтверждением Windows. Если winget недоступен, пользователь отказался или установка не удалась, откроется официальный сайт Node.js; после ручной установки повторно запустите установщик.
3. Установщик копирует приложение в выбранную папку, запускает локальный хост и открывает `http://127.0.0.1:43127/`. Если на этом порту уже работает другая копия Buildbook, сначала остановите её и повторите установку.
4. При первом запуске хост сам создаст `.env`, сгенерирует секрет локального API и настроит пути профиля и очереди в `%LOCALAPPDATA%\\Buildbook\\data`. Ключ вручную копировать не нужно.
5. При желании установите Buildbook как PWA средствами браузера. Открывайте установленное приложение с того же локального адреса.
6. Перейдите во вкладку Telegram. При работе через локальный хост браузерная сессия создаётся автоматически, без ручного ввода ключа. Нажмите «Настроить бота» и пройдите мастер: введите токен BotFather и свой числовой Telegram user ID. Хост проверит токен через Telegram Bot API и сохранит секрет локально в `.env`.
7. Автозапуск можно включить кнопкой «Установить автозапуск» во вкладке Telegram. Задача Планировщика создаётся для текущего пользователя без повышения прав.

Внешняя страница GitHub Pages и локальный API имеют разные browser origin, поэтому браузер не разрешает им обмениваться сессиями. Используйте PWA, установленную с `http://127.0.0.1:43127/`. `BUILDBOOK_LOCAL_API_TOKEN` генерируется автоматически и нужен только как внутренний секрет хоста; штатный PWA не просит его вводить.

Локальный web host отдаёт только фиксированный список публичных ресурсов интерфейса: `index.html`, необходимые скрипты, библиотеку XLSX, manifest, иконку и Service Worker. `.env`, `.git`, `data/`, профиль, очередь Telegram, логи и произвольные файлы не входят в allowlist и не раздаются. Поддерживаются только GET/HEAD; каталог-листинг отключён. Интерфейс и API используют один hostname и порт. Всегда открывайте приложение по одному и тому же адресу: выберите `http://127.0.0.1:43127/` и не переключайтесь на `http://localhost:43127/` (или наоборот). Для браузера это разные origin: у них раздельные localStorage и host-only HttpOnly-сессии. После смены hostname приложение может открыть IndexedDB, а не выбранный ранее файловый профиль.

## Автозапуск Windows

Основной способ — кнопки «Установить автозапуск» и «Удалить автозапуск» во вкладке Telegram. Они выполняют локальные PowerShell-скрипты через host API, показывают результат в интерфейсе и не открывают отдельную консоль. Для ручного обслуживания доступны команды:

```powershell
.\scripts\install-buildbook-autostart.ps1
```

Задача запускается при входе пользователя, работает без повышенных прав, не создаёт параллельные экземпляры и повторяет запуск после аварийного завершения (до пяти попыток с минутным интервалом). Для удаления:

```powershell
.\scripts\uninstall-buildbook-autostart.ps1
```

Для временной остановки используйте `Stop-ScheduledTask -TaskName 'Buildbook Local Host'`; для запуска — `Start-ScheduledTask -TaskName 'Buildbook Local Host'`.

## Важное ограничение Telegram

Telegram polling **по умолчанию выключен**. Сначала откройте Buildbook через локальный host и пройдите мастер настройки Telegram. Затем в настройках импорта создайте резервную копию IndexedDB, перенесите профиль в пустой файловый профиль, проверьте read-back и SHA-256 и подтвердите переключение на канонический профиль. После перезапуска проверьте, что вкладка Telegram показывает активное каноническое хранилище. Только после этого нажмите «Запустить Telegram» во вкладке Telegram. Вручную менять `BUILDBOOK_TELEGRAM_ENABLED` и перезапускать host не нужно. Если интерфейс остаётся на IndexedDB, Telegram включать нельзя: это два независимых финансовых журнала.

Во вкладке Telegram отображаются последние 50 входящих сообщений с результатом обработки и журнал действий локального хоста. Журнал действий сохраняется в `%LOCALAPPDATA%\\Buildbook\\data\\host-activity.json`, хранит до 500 событий, а интерфейс показывает последние 100. В нём фиксируются настройка и проверка бота, запуск/остановка, изменения белого списка и команд, а также результаты локальных помощников; токены и содержимое финансовых операций в журнал действий не записываются.\n\nПосле включения бот принимает только личные сообщения пользователей из белого списка. Команды: `/доход 1250 Описание`, `/расход 450 Описание`, `/статистика`, `/статистика 2026-11`, `/help`. Подтверждение отправляется после записи операции. Статистика только читает тот же профиль. Обычный текст и чужие пользователи остаются без ответа.

Автозапуск хоста поднимает локальный web/API host на одном loopback-порту. После миграции файлового профиля Telegram запускается и останавливается кнопками в интерфейсе; приложение само обновляет `.env`, перезапускать задачу Планировщика не требуется. Отдельная Windows-служба не используется: локальный host работает как пользовательский процесс и восстанавливается Планировщиком заданий. Режим хранения обычного UI выбирается явно после проверенного импорта; при потере сессии приложение блокирует запуск, а не переключается на IndexedDB автоматически. Настройка режима и cookie-сессия привязаны к origin браузера, поэтому не меняйте hostname после миграции.

Ключ первоначального подключения обменивается на HttpOnly-сессию с `SameSite=Strict` и сроком 12 часов; повторное подключение отзывает предыдущую сессию. Когда интерфейс раздаётся тем же локальным хостом, PWA может запросить такую сессию через same-origin bootstrap без ручного ключа. Этот маршрут недоступен для внешнего статического интерфейса и не принимает cross-origin запросы. Браузерный JavaScript не получает значение cookie. Если сессия истечёт, Buildbook остановит редактирование: сначала скачайте резервную копию текущей вкладки, нажмите «Повторно подключить хост», затем после успешной проверки сессии выберите «Загрузить актуальный профиль». Так приложение не перезапишет более свежие данные устаревшим состоянием. Токен Telegram-бота вводится в мастере интерфейса и отправляется только локальному host API; после сохранения он не возвращается браузеру и хранится в `.env`. Локальный хост пишет журнал в `data/local-host.log`; при запуске, если файл уже больше 5 МБ, предыдущий журнал переносится в `.1` (во время одной длительной сессии размер файла автоматически не ограничивается).

## Безопасность

- Не коммитьте `.env`; он исключён через `.gitignore`.
- Не отправляйте `.env` в чат и не вставляйте токен Telegram-бота во вкладку браузера.
- Используйте только loopback-адреса для локального API.
- Не открывайте порт локального API в сеть и не меняйте bind host на `0.0.0.0`.
- Регулярно создавайте резервные копии профиля.
