# Локальный профильный API

Модуль `host/local-api.mjs` предоставляет минимальный HTTP API поверх `createProfileStore`. Он пока не запускается автоматически: интеграция в жизненный цикл локального хоста и клиентский адаптер — следующие задачи.

## Маршруты

- `GET /api/health` — проверка доступности процесса.
- `GET /api/profile` — возвращает `{ revision, profile }`; до первого сохранения профиль равен `null`.
- `PUT /api/profile` — принимает `{ expectedRevision, profile }` и возвращает новую ревизию. Устаревшая ревизия даёт HTTP 409 и код `BUILD_BOOK_STORAGE_CONFLICT`.

API принимает JSON до 8 MiB. Ошибки формата возвращаются как 400, неподдерживаемый тип содержимого — 415. Запросы с посторонним `Origin` или `Host` отклоняются. Сервис разрешено привязывать только к loopback-интерфейсу, не к LAN или публичному адресу.

## Граница безопасности

Это локальный транспортный слой, а не полноценная аутентификация. Проверки Host/Origin и loopback binding снижают риск удалённого доступа через браузер, но не защищают от другого локального процесса под тем же пользователем. Перед подключением к чувствительным данным нужно добавить секрет сессии/токен и безопасную выдачу его браузерному клиенту; токен Telegram-бота никогда не должен попадать в этот API или клиентский код.

API пока не подключён к существующему IndexedDB-репозиторию. До реализации миграции и восстановления профиля не использовать его как единственный источник данных.
