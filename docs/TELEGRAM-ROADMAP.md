# План развития Telegram в Buildbook

## Очерёдность реализации

- [ ] **1. Пошаговый мастер подключения в интерфейсе:** токен и Telegram user ID, проверка ввода, сохранение локальным хостом.
- [ ] **2. Проверка Telegram Bot API:** `getMe`, имя, username и ID бота без возврата токена в браузер.
- [ ] **3. Журнал:** последние входящие сообщения, время приёма, результат обработки и безопасные ошибки.
- [ ] **4. Команды:** просмотр, добавление, изменение, удаление и синхронизация через `getMyCommands` / `setMyCommands`.
- [ ] **5. Автовосстановление локального хоста:** перезапуск после аварии, ограничение попыток и задержка.
- [ ] **6. Достоверный статус:** отдельно доступность хоста, валидность токена, polling, последнее получение и успешная обработка.
- [ ] **7. Единый современный интерфейс:** минимум действий в командной строке; BAT/PowerShell остаются только для системных действий Windows и первоначального старта.

## Требования безопасности

- Токен никогда не возвращается браузеру и не записывается в IndexedDB/localStorage, DOM после отправки, логи или Git.
- Bot API и запись секретов выполняются локальным хостом.
- Только loopback, действующая HttpOnly-сессия и строгая проверка данных.
- Telegram выключен по умолчанию; включение возможно только после явного подтверждения и проверки канонического файлового профиля.
- Запись `.env` атомарная, с резервной копией и ограничением ACL в Windows.

## Приёмка

Готовность подтверждается пользовательским сценарием в интерфейсе, целевыми проверками безопасности и проверкой поведения локального хоста на Windows. Сам факт запуска процесса не считается доказательством получения и обработки сообщений.
